# ExiQoian Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Validate-only Ask AI panel with ExiQoian, a project-scoped, persona-aware chat assistant on every project screen that answers only from the project's Neo4j memory with inline phase citations, declines off-topic questions and prompt injection with fixed replies, persists each user's conversations and audits every question.

**Architecture:** A pure pipeline in `engine/exiqoian/` (normalise → injection check → intro → off-topic pre-filter → phase-diversified retrieval through SP2's `MemoryRetriever` → source scrub → grounding → model or no-model composer → output validation) produces a `CitedText` (`engine/citations/`, shared with sub-project 4). `api/app/services/exiqoian.py` adds persistence (`chat_conversations`, `chat_messages`), the project lexicon, rate limit and audit; `api/app/routers/exiqoian.py` streams the validated answer as SSE over `POST` with its own guard that lets viewers chat. The web gets shared citation components and a slide-over panel mounted in `Chrome`.

**Tech Stack:** Python 3.11, FastAPI, sse-starlette, SQLAlchemy async, Alembic, Pydantic 2, PyYAML (tests), Next.js 15, React 19, TanStack Query 5, Tailwind 3.4, lucide-react, Playwright 1.56.

**Spec:** `docs/superpowers/specs/2026-10-25-exiqoian-design.md`

**Depends on sub-project 2 (verified by Task 1, which fails fast if any is missing):**
- `engine/memory/model.py`: `Citation` (`uid, label, phase, revision, artifact_type, artifact_id: str | None, process_id, path`), `MemoryHit` (`uid, label, kind, text, score, keyword_score, vector_score, citation`), `KNOWLEDGE_LABELS`, `NODE_LABELS`.
- `engine/memory/search.py`: `MemoryRetriever` Protocol with `retrieve(project_id, query, *, labels, side, phase, k, as_of, min_terms, vector_floor, include_obsolete)`; `MemoryGraph` implements it.

## Global Constraints

- Branch: work and commit on `feat/gmf-deploy` only; never create a branch; never push. Commit with `git add <the task's files>` only (another agent may be working on the same tree): never `git add -A`, `git stash`, `git reset` or `git checkout -- <path>`.
- No outbound hosts: no new external URL in code or bundle, no new npm or Python runtime dependency; `make egress-audit` passes.
- Viewer read-only server-side: only the `/exiqoian/*` routes accept a viewer `POST`/`DELETE` (`require_chat_user`); every other viewer write still answers 403 `viewer is read only`.
- Fixed reply copy is exactly the spec's (section 1, "Fixed replies"); tests compare by equality with the constants in `engine/exiqoian/replies.py`.
- Limits: question 1–2000 characters (422 otherwise); 12 questions per user per rolling 60 s (429 `slow down: ExiQoian takes 12 questions a minute`); `MAX_SOURCES = 10`; history 6 messages × 600 characters; audit question ≤ 500 characters; conversation title ≤ 80; conversation list 50; lexicon cache 300 s; model `max_tokens=900`.
- Retrieval groups exactly: knowledge `KNOWLEDGE_LABELS` k=8; old code `("Process", "Activity")` k=4; new code `("Class", "Method")` k=4; decisions `("GateDecision", "Error", "Curation")` k=3; `min_terms=2`; default floors; obsolete excluded.
- `mask_sensitive` on every question and answer before storage, audit, history and the model.
- Every untrusted prompt value is inside its own tag with `<source`, `</source`, `<history`, `<question`, `<system` escaped to `&lt;…`.
- Offline tests: engine tests use a fake retriever and `FakeProvider`; API tests override `get_retriever`; only the tests marked as such use `memory_client` (Neo4j).
- Existing suites stay green apart from tests this plan deliberately rewrites (`validate-design.spec.ts` Ask section): `.venv/bin/pytest`, `make e2e`; `.venv/bin/ruff check .` clean; `cd web && npm run typecheck && npm run lint` clean.

## Review Focus

- A follow-up like "and its tests?" after an on-topic answer: retrieval appends the previous user question's terms, so it is answered (not declined as `too_vague`) when the conversation has a prior on-topic question. Test in Task 4 (`test_follow_up_uses_previous_question_terms`) and Task 2 (`too_vague` skipped when `has_context=True`).
- A process name containing an off-domain word (`CookDealerRates`, `WeatherFeedSync`) and questions with numbers ("What happens after 2 retries?"): answered, not declined. Test in Task 2 (`test_project_words_override_off_domain_lexicon`, `test_numbers_in_a_real_question_are_not_arithmetic`).
- The stream is dropped mid-answer (tab closed, Stop): the assistant message is still stored once and the conversation reloads with it; no duplicate on retry. Test in Task 7 (`test_message_is_stored_before_streaming_starts`).
- Memory is down (Neo4j stopped) while the panel is open: the answer is `UNAVAILABLE_REPLY` with an `error` event, nothing raises, the question is audited with verdict `unavailable`. Test in Task 7.
- An answer whose text contains an emoji or non-BMP character before a cited sentence: chip offsets stay on the right sentence in the web. Test in Task 3 (`test_offsets_are_code_points`); Task 8's `segments` slices with `Array.from` (code points), and Task 10's on-topic test asserts every chip's preceding text ends a sentence of the answer.
